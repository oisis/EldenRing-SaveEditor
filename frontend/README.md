# SaveForge 2.0 frontend

The production desktop frontend of SaveForge 2.0. It runs inside the Wails 2
host defined by `wails.json` and `main.go` in the repository root, and it talks
to the backend exclusively through Wails method calls.

## Required toolchain

| Tool | Version | Pinned by |
| --- | --- | --- |
| Node.js | 24.20.0 | `.node-version`, `engines.node` |
| pnpm | 11.24.0 | `packageManager` |

Every dependency in `package.json` is an exact version. Ranges (`^`, `~`,
`latest`), `overrides`, `resolutions` and `patchedDependencies` are not used.

## Commands

Run from the repository root:

```bash
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend run i18n:extract    # update the .po catalogs from the sources
pnpm --dir frontend run i18n:compile    # compile the catalogs (build output, untracked)
pnpm --dir frontend run format:check
pnpm --dir frontend run lint
pnpm --dir frontend run check
pnpm --dir frontend run typecheck       # typecheck:app && typecheck:config
pnpm --dir frontend run test            # Vitest, single run
pnpm --dir frontend run build           # Vite production bundle into frontend/dist
```

The repository `Makefile` wraps the same commands as `make frontend-check`,
`make frontend-test`, `make frontend-build`, `make bindings` and
`make app-build`.

Run the tests and the build sequentially: both use `frontend/dist`.

## Layer structure

```
src/
  main.tsx                 composition root: picks the concrete port implementation
  App.tsx                  foundation screen
  application/             ports, TanStack Query keys and public hooks
  infrastructure/bridge/   the Wails adapters implementing the application ports
  features/                feature modules composed from the application layer and UI
  ui/                      shared design tokens, themes and canonical components
  i18n/                    Lingui runtime and the single list of supported locales
  locales/                 .po message catalogs
  test/                    shared test helpers and the architecture checks
```

Dependency direction:

- `features` depends on the application layer and on `ui`.
- The application layer declares the ports it needs and depends on nothing
  below itself — in particular not on `infrastructure`.
- `infrastructure` implements those ports.
- Only `main.tsx` chooses which implementation is used.

## Rules enforced by `src/test/architecture.test.ts`

- **Only infrastructure imports Wails.** Just
  `src/infrastructure/bridge/applicationInfoBridge.ts` may import
  `frontend/wailsjs`. Feature modules, UI components and the application layer
  must not, and component tests mock the port, never the generated bindings.
- **No HTTP.** The application never uses `fetch`, `XMLHttpRequest`,
  `WebSocket`, `EventSource`, `navigator.sendBeacon`, `node:http`/`node:https`,
  Axios or GraphQL. The application starts no local server and opens no port.
  This is a regression check over the known forbidden transport paths, not a
  proof that no network client of any shape could ever be written.
- **`skipLibCheck` scope.** `tsconfig.json` (`src`, `wailsjs`) keeps
  `strict: true` with an explicit `skipLibCheck: false`. `tsconfig.node.json`
  (`vite.config.ts`, `lingui.config.ts`) keeps `strict: true` with
  `skipLibCheck: true`. That exception covers build-time plugin declarations
  only and must never widen to application code.
- **Colour values live in `src/ui/tokens/`.** Components reference semantic
  tokens; themes substitute values for them.

## Generated bindings

`frontend/wailsjs/` is generated by `wails generate module` (`make bindings`).
It is tracked by design and **must never be edited by hand**: rerun the
generator after any change to the bound Go methods or their result types.

## Scope of the current slice

Implemented:

- one vertical flow: `GetApplicationInfo` endpoint → Wails host bridge →
  generated binding → infrastructure adapter → application port → TanStack
  Query → React component;
- the first desktop save-session flow: the native file chooser, `LoadSave`,
  source metadata, the active and inactive character list, full validation of
  every active slot before accepting a session, warning-report presentation,
  and confirmed `CloseSave` cleanup;
- loading, success and a safe error state with Retry;
- the shared token contract with the `Light`, `Dark` and `Elden Ring` themes,
  the canonical `Button`, `Card` and `Badge`, a visible focus ring and
  `prefers-reduced-motion`;
- Lingui localization with English as the source and fallback locale, and a
  Polish catalog used to prove switching and fallback.

Not implemented yet, and deliberately absent from this slice: the application
shell and main navigation, `Save`, `Save As`, Character editing, the production
Inventory & Storage, Item Database and Equipment screens, World, Templates,
Tools, Settings, deployment and SSH, and update checks. The language list of
the first release is not decided here, and no visible language selector in
`Tools → Settings` exists yet.
